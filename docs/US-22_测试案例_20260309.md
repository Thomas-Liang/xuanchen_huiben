# US-22 测试案例（2026-03-09）

## 一、测试范围

覆盖任务队列中心 V1 能力：

- 加入队列
- 自动执行
- 暂停/继续
- 取消
- 重试
- 清理已结束
- 重启恢复
- 测试模式（模拟延迟/定点失败）
- **并发调度**

## 二、测试用例

| 用例ID | 用例名称          | 步骤                                                     | 预期结果                                             |
| ------ | ----------------- | -------------------------------------------------------- | ---------------------------------------------------- |
| T22.1  | 加入队列成功      | 解析或拆分后点击“加入队列”                               | 队列出现新任务，状态为 `pending`，随后进入 `running` |
| T22.2  | 任务自动执行      | 队列存在 `pending` 任务                                  | 自动执行，进度 `current/total` 递增                  |
| T22.3  | 暂停任务          | 运行中点击“暂停”                                         | 当前分段完成后状态变 `paused`，不再发起下一条        |
| T22.4  | 继续任务          | 对 `paused` 任务点击“继续”                               | 状态回到 `pending/running` 并继续执行                |
| T22.5  | 取消任务          | 运行中或待执行任务点击“取消”                             | 状态变 `cancelled`，后续不再继续                     |
| T22.6  | 失败后重试        | 构造 `failed/cancelled` 任务后点击“重试”                 | 任务状态重置为 `pending`，进度重置并重新执行         |
| T22.7  | 清理已结束        | 队列含 completed/failed/cancelled 任务，点击“清理已结束” | 仅保留 pending/running/paused 任务                   |
| T22.8  | 重启恢复          | 存在队列任务时关闭并重启应用                             | 队列元数据恢复；重启前 running 任务转为 paused       |
| T22.9  | 测试模式-延迟     | 开启测试模式，设置模拟延迟                               | 任务按延迟推进，无真实 API 调用                      |
| T22.10 | 测试模式-定点失败 | 开启测试模式并设置失败序号                               | 指定序号稳定失败，可复现重试流程                     |
| T22.11 | 并发数=1          | 设置并发数1，加入5个场景                                 | 任务逐个执行，同时只有1个进行中                      |
| T22.12 | 并发数=3          | 设置并发数3，加入5个场景                                 | 同时最多3个进行中，进度跳跃式增长                    |
| T22.13 | 并发暂停          | 并发=3时点击暂停                                         | 当前批次完成后停止，不再启动新任务                   |
| T22.14 | 并发取消          | 并发=3时点击取消                                         | 立即停止，未完成任务状态正确                         |
| T22.15 | 并发失败策略      | 并发=2，失败序号=3，失败策略=继续                        | 3失败后4,5继续执行                                   |
| T22.16 | 并发失败停止      | 并发=2，失败序号=3，失败策略=停止                        | 3失败后停止，4,5不执行                               |

## 三、建议回归组合

1. **真实 API 快速回归**
   - 3~5 个场景
   - 失败策略 `continue`
   - 验证暂停、继续、取消、重试

2. **稳定复现回归（测试模式）**
   - 模拟延迟：1000~1500ms
   - 失败序号：3
   - 全流程回归：加入 -> 运行 -> 暂停 -> 继续 -> 失败 -> 重试

3. **并发调度回归（测试模式）**
   - 模拟延迟：800~1200ms
   - 测试场景：5个
   - 并发数分别测试：1, 2, 3, 5
   - 组合测试：并发 + 暂停、并发 + 取消、并发 + 失败策略
