## 一、项目概述

### 1.1 项目背景

泫晨懿然·灵犀绘梦助手是一款基于 Tauri + React 开发的 AI 绘画桌面应用，支持 Seedream 和 Banana 2 两大 AI 绘画模型。本版本在 V1.0 基础上进行全面升级，包括现代化 UI、完整历史记录、多账号池管理以及 OpenClaw Skill 深度集成。

### 1.2 技术栈

| 技术     | 版本                        | 说明     |
| -------- | --------------------------- | -------- |
| 前端框架 | React 19                    | 用户界面 |
| 语言     | TypeScript 5.8              | 类型安全 |
| 构建工具 | Vite 7                      | 快速构建 |
| 桌面框架 | Tauri 2.x                   | 桌面应用 |
| UI组件   | Ant Design 6 + Tailwind CSS | 界面样式 |
| 状态管理 | Zustand 5                   | 状态管理 |
| 动画库   | Framer Motion               | 交互动画 |
| 数据库   | SQLite (后期) / JSON (快速) | 数据存储 |
| 后端     | Rust + Axum                 | HTTP服务 |

### 1.3 项目目标

- 提供现代化 UI/UX 体验，支持亮/暗主题
- 实现完整的生成历史记录和参考图库管理
- 支持 OpenClaw Skill 多实例集成
- 实现多 API 账号池管理和智能调度

**智能调度算法设计**:

```
┌─────────────────────────────────────────────────────────────────┐
│                    智能账号选择流程                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 接收生成请求                                                │
│         ↓                                                       │
│  2. 获取所有可用账号列表 (is_active = true)                     │
│         ↓                                                       │
│  3. 过滤条件检查:                                                │
│     ├── 每日限制检查 (used_today < daily_limit)                 │
│     ├── 速率限制检查 (距离上次使用 > 间隔)                        │
│     └── 健康状态检查 (最近失败率 < 阈值)                          │
│         ↓                                                       │
│  4. 账号评分计算:                                                │
│     Score = (优先级权重 * 优先级) +                              │
│            (可用额度权重 * 剩余额度比例) +                        │
│            (健康度权重 * (1-失败率)) +                           │
│            (最近使用权重 * 距离上次时间)                         │
│         ↓                                                       │
│  5. 选择最高分账号                                               │
│         ↓                                                       │
│  6. 执行API调用                                                 │
│         ↓                                                       │
│  7. 记录使用日志                                                 │
│         ↓                                                       │
│  8. 成功/失败处理:                                              │
│     ├── 成功 → 更新last_used_at, used_today                     │
│     └── 失败 → 标记失败次数 → 尝试下一个账号                     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 11.1 建议执行顺序（按依赖）

为降低并行开发冲突，建议按以下顺序推进：

1. **第一阶段（基础能力层）**  
   先完成 `US-22`（任务队列中心）与 `US-23`（高级检索）。
   - 原因：两者主要沉淀调度能力、查询能力和状态管理能力，是后续“复用/导出”的基础。

2. **第二阶段（效率增强层）**  
   完成 `US-24`（结果对比与参数复用）与 `US-25`（模板2.0）。
   - 原因：二者直接复用第一阶段的历史筛选、任务触发链路，可并行但共享同一批接口规范。

3. **第三阶段（治理与交付层）**  
   完成 `US-26`（智能整理）与 `US-27`（项目导出包）。
   - 原因：智能整理会新增图库元数据，导出包需要消费这些元数据，先治理再导出更稳妥。

4. **推荐并行策略**
   - 后端优先实现：`T22.1~T22.3`、`T23.1`、`T25.1`、`T27.1~T27.3`
   - 前端跟进实现：`T22.4`、`T23.2/T23.4`、`T24.x`、`T25.2`、`T27.5`
   - 联调窗口集中在每阶段末尾，避免持续打断开发节奏。

5. **阶段性验收里程碑**
   - 里程碑 A：队列可控 + 高级筛选可用（US-22/23 Done）
   - 里程碑 B：可对比、可复用、可管理模板（US-24/25 Done）
   - 里程碑 C：图库可治理 + 一键交付导出（US-26/27 Done）
